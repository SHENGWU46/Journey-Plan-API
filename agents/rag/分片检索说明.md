# 景点知识库 · 结构化分片与检索说明

> 适用代码：`agents/rag/document_parser.py`（新增）、`agents/rag/vector_store.py`（`load_document` 改造）、`agents/config/chroma.yml`（新增参数）
> 适用场景：把 `agents/data/*旅游景点.txt` 这批"城市 → 区域 → 景点 → 字段"结构化的景点知识，切成**以单个景点为单位、语义完整、带结构化元数据**的向量分片，供 RAG 检索使用。

---

## 1. 为什么要改（旧逻辑的问题）

旧逻辑在 `vector_store.py` 的 `load_document` 中，对 txt 走的是：

```python
documents = get_file_documents(path)            # TextLoader 把整个 txt 读成 1 个 Document
split_document = self.spliter.split_documents(documents)   # RecursiveCharacterTextSplitter
```

其中切分器配置为 `chunk_size=350, chunk_overlap=50`，按字符数硬切。源文件是结构化的（如下），按 350 字符窗口硬切会带来三个问题：

1. **跨景点混合**：一个 350 字符窗口常把"普达措尾部 + 纳帕海 + 虎跳峡头部"拼进同一片，向量被多个景点信息"平均"，具体景点检索命中噪声。
2. **景点被截断**：一个景点的"描述 / 预算 / 游玩时间 / 最佳季节 / 交通方式"被切到两片，检索回来信息残缺。
3. **无结构元数据**：分片只带 `source`，检索层无法按城市 / 区域 / 景点过滤。

---

## 2. 新方案（方案 C：结构化分片 + 超长续切）

- **txt 文件**：按源文件既有层级（区域 → 景点 → 字段）解析，**每个景点生成 1 个 Document**；单景点内容超长（> `max_attraction_chars`）时，再按句细分为多个子分片，每段保留景点 header 上下文。
- **pdf 文件**：维持原 `RecursiveCharacterTextSplitter` 字符切分逻辑不变（pdf 无此结构化约定）。
- **元数据**：每个分片携带 `source / city / region / attraction`，方便后续过滤与增强输出。

---

## 3. 源文件格式约定

13 个 `XX旅游景点.txt` 均遵循如下缩进约定（已在 `澳门 / 厦门 / 香格里拉 / 川西 / 香港` 等多文件抽样核对一致）：

| 层级 | 缩进 | 特征 | 示例 |
|------|------|------|------|
| 区域标题 | 0 缩进 | 以 `：` 结尾 | `澳门半岛：` |
| 景点名 | 2 缩进 | 以 `：` 结尾 | `  大三巴牌坊及议事亭前地：` |
| 字段行 | 4 缩进 | 含冒号 `：`，`字段：值` | `    描述：藏语意为...` |
| 字段续行 | 4 缩进 | 无冒号，视为上一字段的延续 | （长描述折行） |

文件首行为标题（如 `澳门（中国澳门）旅游景点知识库`），可能有一行括号注释（`(货币以澳门元MOP计...)`），均不参与解析。

## 4. 解析器 `document_parser.py` 逐段详解

### 4.1 常量与辅助函数

```python
REGION_INDENT = 0      # 区域标题缩进
ATTR_MAX_INDENT = 4    # 景点标题缩进 < 4
FIELD_INDENT = 4       # 字段行缩进 >= 4
```

- `_leading_spaces(line)`：统计行首空格数，用来判断层级。
- `_split_colon(text)`：按**第一个**冒号（`：`/`:`）把 `字段：值` 拆成 `(key, value)`；值里再出现冒号也不会误拆。
- `_city_from_path(path)`：从文件名 `XX旅游景点.txt` 反推城市名（去掉 `旅游景点.txt` 后缀）；pdf 走同样规则，其它文件退回扩展名剥离。

### 4.2 主流程 `parse_attraction_txt`

签名：`parse_attraction_txt(path, max_chars=512, sub_size=200) -> list[Document]`

逐行扫描，用三个状态变量累积一个景点：`region / attraction / fields`（`fields` 为 `[(key, value), ...]`）。

行分类逻辑（按顺序匹配，命中即 `continue`）：

1. **区域标题**：`indent == 0 and 行尾 == "："` → 先 `flush()` 收尾上一个景点，再把区域名存入 `region`。
2. **景点标题**：`0 < indent < 4 and 行尾 == "："` → `flush()` 收尾上一个景点，把景点名存入 `attraction`。
3. **字段行**：`indent >= 4 and 含冒号` → 用 `_split_colon` 拆出 `(k, v)` 追加到 `fields`。
4. **字段续行**：`indent >= 4 and fields 非空 and 无冒号` → 把本行文本拼到上一个字段的值后面（处理折行长描述）。
5. **其它**（标题说明、括号注释等）→ 忽略。

`flush()` 闭包：当当前景点 `attraction` 与 `fields` 都非空时，组装并写入分片，然后清空状态：

```python
def flush():
    if attraction and fields:
        header = f"{attraction}（{city}·{region}）"
        body = "\n".join(f"{k}：{v}" for k, v in fields)
        docs.extend(_to_docs(path, city, region, attraction, header, body, max_chars, sub_size))
    attraction = ""
    fields = []
```

最终分片的 `page_content` 形如：

```
纳帕海（香格里拉·市区及近郊（香格里拉市））
描述：季节性高原湖泊与湿地，夏季是草原、冬季成海……
预算：环湖免费（骑马/骑行约80-150元）；依拉草原部分区域收费。
游玩时间：半天。
最佳季节：6-8月（草原）、11-3月（观鸟、海景）。
交通方式：市区骑行或打车约20分钟，可环湖自驾。
```

> 注：header 里 `region` 有时自带城市括号（如 `市区及近郊（香格里拉市）`），会与 `city` 重复，属无害展示瑕疵，不影响向量检索。

### 4.3 超长细分 `_to_docs`

```python
def _to_docs(path, city, region, attraction, header, body, max_chars, sub_size):
    meta = {"source": path, "city": city, "region": region, "attraction": attraction}
    content = f"{header}\n{body}"
    if len(content) <= max_chars:
        return [Document(page_content=content, metadata=meta)]

    # 超长：按句细分，每段保留 header 上下文
    chunks, buf = [], ""
    for seg in re.split(r"(?<=[。！？!?；;])", body):
        if not seg.strip():
            continue
        if buf and len(buf) + len(seg) > sub_size:
            chunks.append(f"{header}\n{buf}")
            buf = seg
        else:
            buf += seg
    if buf:
        chunks.append(f"{header}\n{buf}")
    return [Document(page_content=c, metadata=meta) for c in chunks]
```

- 普通景点（内容 ≤ `max_attraction_chars`，绝大多数情况）：**一景点一片**。
- 个别超长景点：按句（`。！？!?；;`）切分，每段累积到接近 `sub_chunk_size` 时落成一个分片，且**每段都重新拼上 header**，保证截断后依然知道属于哪个景点，并保留全部结构化元数据。

## 5. `vector_store.py` 的接线改造

### 5.1 `load_document` 按文件类型分流

```python
try:
    if path.endswith(".txt"):
        # 结构化解析：每景点一片（超长再按句细分）
        documents = parse_attraction_txt(
            path,
            max_chars=chroma_conf.get("max_attraction_chars", 512),
            sub_size=chroma_conf.get("sub_chunk_size", 200),
        )
        if not documents:
            # 兜底：解析不出景点（格式异常）时退回整文件字符切分
            logger.warning(f"[加载知识库]{path}未解析出景点，退回整文件切分")
            documents = get_file_documents(path)
            documents = self.spliter.split_documents(documents)
    else:
        documents = get_file_documents(path)
        documents = self.spliter.split_documents(documents)

    if not documents:
        logger.warning(f"[加载知识库]{path}内没有有效文本内容，跳过")
        continue

    split_document = documents
    ...
    self.vector_store.add_documents(split_document)
```

要点：
- txt 走 `parse_attraction_txt`，产出已是"每景点一片"的 `Document` 列表，**不再**过 `RecursiveCharacterTextSplitter`（避免二次切碎）。
- 解析结果为空（格式不符）时自动回退到旧字符切分，保证不丢数据。
- pdf 维持旧路径不变。
- 之后流程（`md5` 去重、`add_documents` 入库、日志）完全复用，未改动。

### 5.2 检索侧 `get_retriever`

```python
def get_retriever(self, k: int | None = None):
    k = k or chroma_conf["k"]      # 不传则用配置默认值 5
    return self.vector_store.as_retriever(search_kwargs={"k": k})
```

- 检索层本身没改；分片变"每景点一片"后，检索具体景点会直接命中该景点的**完整、连贯**信息块。
- `k` 控制返回分片数：`k=5`（conf 默认）适合宽泛检索，`k=3` 适合查具体景点。上层 `rag_summarize` 工具的 `top_k` 现已设为**必填整数**（首次传 10、具体传 3），避免 LLM 省略后回落到 conf 的 5。

## 6. 配置项（chroma.yml）

```yaml
# 结构化分片：每景点独立成片，超过 max_attraction_chars 再按句细分
max_attraction_chars: 512   # 单景点分片上限；超过才走 _to_docs 的按句细分
sub_chunk_size: 200         # 超长景点按句细分时，每个子分片的目标长度
```

`chunk_size / chunk_overlap / separators` 仍保留，仅供 **pdf** 走旧 `RecursiveCharacterTextSplitter` 使用。

## 7. 重建索引（让新分片生效）

改了切分逻辑后，旧的 `chroma_db` 里还是旧分片，必须重建：

1. 停止后端（运行中的向量库单例持有旧 collection）。
2. 清空旧索引与去重记录：
   - 删除 `journey-plan-api/chroma_db/` 目录
   - 删除 `journey-plan-api/md5.text`
3. 重新加载（会重新调用 DashScope 做 embedding）：
   ```bash
   cd journey-plan-api
   # 使用装有 langchain 的运行环境（如 conda 的 fastapi-env）
   python -c "from agents.rag.vector_store import VectorStoreService; VectorStoreService().load_document()"
   ```
4. 重启后端，使 agent 单例加载新的向量库。

## 9. 已知瑕疵与可拓展点

- **header 冗余**：当 `region` 自带城市括号时（如 `市区及近郊（香格里拉市）`），header 会写成 `纳帕海（香格里拉·市区及近郊（香格里拉市））`。如需整洁，可在 `flush()` 里把 `region` 末尾 `（…）` 剥掉。
- **阈值**：`max_attraction_chars=512` 使绝大多数景点保持整片；如希望更细粒度，可调小该值，超长景点会更早进入按句细分。
- **兜底增强**：`parse_attraction_txt` 返回空时回退到旧字符切分，已保证鲁棒性；若希望更严格，可在回退前对异常文件告警。
- **pdf**：仍用字符切分，如 pdf 也具备结构化层级，可复用同一套缩进解析逻辑。
